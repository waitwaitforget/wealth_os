# ADR-0001：采用模块化单体与端口适配器

- 状态：Accepted
- 日期：2026-08-05

## 背景

系统会包含数据、研究、组合、风险、回测、校验和 UI。早期请求量低，但金融语义复杂。

## 决策

采用单仓库、模块化单体和 Ports & Adapters。领域层与外部基础设施分离，暂不拆微服务。

## 备选方案

- 微服务：部署隔离强，但当前运维和一致性成本过高；
- 单脚本/Notebook：开发快，但无法长期维护；
- 完全绑定量化平台：上线快，但锁定框架。

## 结果

优点：低运维成本、事务简单、可测试、未来可拆分。缺点：需要严格 import 边界，单体可能随功能增长变大。

## 后续

使用 import-linter 和目录规范强制边界；只有出现独立扩容、权限或发布需求时才拆服务。
