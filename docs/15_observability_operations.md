# 15. 可观测性与日常运行

## 1. 目标

系统需要持续回答：数据是否更新、任务是否成功、策略是否异常、账户是否对账、用户是否需要行动。

## 2. 三类信号

### Logs

结构化日志记录运行上下文和异常。

### Metrics

至少包括：

- 数据更新时间和延迟；
- 任务成功率和耗时；
- 缺失率和异常率；
- 因子分布漂移；
- Validation Error 数量；
- 组合 NAV、回撤、波动率；
- 影子与实际偏差；
- API 延迟和错误率。

### Traces

当系统拆分任务或服务后，用 trace 关联数据更新、因子、决策和 API 请求。首版可先使用 run_id。

## 3. 定时任务

- 市场数据更新；
- 汇率和利率更新；
- 特征和因子计算；
- 组合决策；
- Validation；
- 每日账户对账；
- 周报/月报；
- 数据回查和修订。

任务必须幂等，并支持重跑指定日期。

## 4. 报警等级

- Info：正常完成；
- Warning：数据延迟、轻微偏差；
- Error：决策或报告受影响；
- Critical：会计错误、错误订单、实盘风险。

Critical 必须阻断交易并触发 Kill switch。

## 5. 数据新鲜度

每个数据集定义 SLA：

- 市场收盘后多久应完成；
- 最大允许陈旧时间；
- 失败时可否使用上一版本；
- 哪些功能必须停止。

不能统一“继续使用旧数据”。

## 6. 运行手册

针对以下事件编写 Runbook：

- 数据源不可用；
- 价格异常；
- 汇率缺失；
- 回测结果变化；
- 账户对账失败；
- 部分成交；
- 券商接口故障；
- 数据库损坏；
- 发布回滚。

## 7. 备份与恢复

- 原始数据和账户数据独立备份；
- 配置和代码由 Git 管理；
- 定期恢复演练；
- 关键结果可由原始数据重算；
- 审计日志采用不可变或追加写。

## 8. 运营面板

内部 Dashboard 展示：

- 今天所有任务状态；
- 数据新鲜度；
- Validation；
- 最新决策；
- 实际/影子差异；
- 当前风险；
- 未处理告警。

## 9. 首版验收

- 所有任务有 run_id；
- 日志结构化；
- 数据更新和 Validation 有指标；
- Error 可通知；
- 重跑不产生重复数据或订单；
- 有最小 Runbook 和恢复流程。
