# 18. 测试策略

## 1. 测试金字塔

- 单元测试：纯函数、领域不变量；
- 属性测试：随机权重、现金流和市场状态；
- 集成测试：数据、存储、回测适配器；
- 契约测试：API、Provider、Broker；
- 回归测试：固定数据和 golden outputs；
- 端到端：数据更新到决策展示；
- 实盘影子测试：模型与实际账户。

## 2. 单元测试

重点：

- 因子手算；
- 交易成本；
- 权重边界；
- 回撤状态机；
- 单位净值、TWR、XIRR；
- 汇率换算；
- 触发器和冷却期。

## 3. 属性测试

使用 Hypothesis 验证：

- 权重始终和为 1；
- 非杠杆现金不为负；
- 入金不改变单位净值；
- 成本增加不会提高最终 NAV；
- 风险上升不会导致风险缩放仓位上升；
- 同一订单重复处理不会重复成交；
- 约束冲突产生明确错误而非非法组合。

## 4. Golden Tests

维护小型、可人工审查的数据集，固定：

- 每日价格；
- 入金；
- 信号；
- 目标权重；
- 订单和成本；
- 期末结果。

任何变更导致结果变化都需说明是修复、语义变更还是回归。

## 5. 无未来信息测试

- 删除或打乱未来数据，历史结果不变；
- 财报公告日前不可使用；
- 收盘后信号不按同一收盘成交；
- 指数成分按历史生效日；
- 调整值和复权不泄漏未来。

## 6. 双引擎测试

对 Native 与 VectorBT 比较逐日：

- NAV；
- unit NAV；
- cash；
- positions；
- orders；
- costs；
- turnover。

对差异设绝对和相对容差，并生成差异文件。

## 7. 性能测试

核心目标不是高频性能，而是：

- 多年、数十资产回测在合理时间完成；
- 参数扫描可并行；
- 数据更新不重复全量处理；
- API 对移动端响应足够快。

性能优化前必须有基准，不能牺牲正确性。

## 8. 覆盖率

覆盖率是门槛，不是目标。建议：

- Domain、Accounting、Validation ≥ 90%；
- Portfolio、Risk ≥ 85%；
- Infrastructure ≥ 70%；
- 总体初始门槛 80%，逐步提高。

关键金融不变量即使只占少量代码也必须 100% 有测试。

## 9. CI 测试矩阵

- Python 3.12；
- Linux 主环境；
- 可选 macOS smoke；
- 核心依赖最低和锁定版本；
- 有/无 VectorBT；
- 文档构建和链接检查。

## 10. 测试数据

- 合成数据明确标注；
- 小型真实数据遵守许可；
- 不提交真实账户和个人数据；
- 固定数据有来源、时间范围和校验和。

## 11. 缺陷回归

每个金融语义 Bug 必须先添加失败测试，再修复。Issue 记录：

- 错误影响的结果；
- 受影响版本；
- 是否需要重算历史；
- 修复后对账；
- 是否触发策略暂停。
