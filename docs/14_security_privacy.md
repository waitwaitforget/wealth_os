# 14. 安全与隐私

## 1. 威胁模型

系统未来可能接触：

- 账户资产和交易记录；
- 个人现金流；
- 数据源 Token；
- 券商 API 凭证；
- 交易建议与执行权限；
- 本地文件和云端部署。

主要风险包括凭证泄漏、未授权交易、数据篡改、依赖供应链攻击和日志泄密。

## 2. 最小权限

- 研究环境默认没有交易权限；
- 券商先接只读权限；
- 下单权限与数据读取权限分离；
- 自动交易需要独立开关和人工审批；
- 每个环境使用独立凭证。

## 3. 密钥管理

- 不将 Token 写入 Git、YAML 或 Notebook；
- 本地使用系统 Keychain 或 `.env`，只保留 `.env.example`；
- 服务端使用 Secret Manager；
- 定期轮换；
- 日志自动脱敏；
- CI 使用最小权限 Secret。

## 4. 数据保护

- 本地敏感数据库和备份加密；
- API 使用 TLS；
- 用户数据与公开市场数据分区；
- 导出文件标记敏感级别；
- 定义数据保留和删除策略；
- 不把真实账户数据上传到公开实验平台。

## 5. 鉴权与授权

首版单用户仍应采用身份认证。未来角色：

- Viewer；
- Researcher；
- Approver；
- Executor；
- Admin。

交易批准应支持二次认证和操作审计。

## 6. 交易安全

- 默认 paper trading；
- 订单金额、单日成交和资产类别有硬限制；
- 实盘下单前重新校验价格、现金和风险；
- 防重复订单的幂等键；
- Kill switch；
- 异常价格和数据陈旧时禁止下单；
- 人工批准记录不可修改。

## 7. 供应链安全

- 锁定依赖；
- Dependabot/Renovate；
- 安全扫描；
- 避免不明来源量化包；
- Docker 镜像最小化；
- 定期检查已知漏洞。

## 8. 审计

所有敏感操作记录：

- 谁；
- 何时；
- 做了什么；
- 使用哪个版本和数据；
- 修改前后值；
- 是否通过审批；
- 结果和异常。

## 9. 首版验收

- 仓库无明文密钥；
- `.env.example` 完整；
- 敏感日志脱敏；
- API 至少有基础鉴权；
- 实盘功能默认关闭；
- 订单有幂等和金额上限；
- 安全扫描进入 CI。
