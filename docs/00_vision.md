# 00. 项目愿景与边界

## 1. 愿景

Wealth OS 是一个服务于个人长期财富积累的研究级、可解释、可验证的多资产投资操作系统。它不以预测每一次市场涨跌为目标，而是持续回答四个问题：

1. 当前总资本应该承担多少市场风险；
2. 资本应如何分配到 Core、Satellite、另类资产和现金；
3. 新增资金应该投入多少、投向哪里、保留多少现金；
4. 每一次调仓建议由哪些信号、风险约束和交易成本共同驱动。

## 2. 目标用户

第一阶段只服务单一高级用户，即系统所有者本人。设计时仍采用产品级和多用户可扩展边界，但不为尚不存在的用户规模提前建设复杂权限与多租户架构。

典型用户特征：

- 投资周期 10 年以上；
- 资金持续流入；
- 主要配置 A 股、港股、美股宽基；
- 允许少量行业、个股和 BTC 追求 Alpha；
- 重视长期复利、最大回撤与决策可解释性；
- 不使用杠杆或仅在未来经过独立治理后考虑。

## 3. 核心投资结构

系统默认采用可调整的 Core–Satellite 结构：

- **Core**：宽基指数、债券、黄金及其他长期风险溢价资产；
- **Satellite**：行业轮动、个股多因子、机器学习 Alpha 和主观研究仓位；
- **Alternative**：BTC 等无法使用传统现金流估值的高波动资产；
- **Cash**：人民币现金、美元现金及其低风险现金管理工具。

Core 与 Satellite 允许互调资金，但必须由资本分配规则和风险预算约束，不能仅凭近期收益追涨。

## 4. 设计原则

### 4.1 Cash is an Asset

现金不是未完成配置的残差，而是有币种、收益率、目标权重、风险作用和机会成本的正式资产。

### 4.2 Risk First

策略首先证明风险行为符合预期，其次才评价收益。任何超额收益必须在交易成本、汇率、税费和承担风险后重新归因。

### 4.3 Validation before Optimization

先证明数据、会计和实现正确，再优化参数和收益。未经校验的漂亮回测没有决策价值。

### 4.4 Explainability by Construction

解释不是回测结束后附加的文字，而应由信号贡献、风险约束、目标权重变化和订单生成过程天然产出。

### 4.5 Point-in-Time by Default

所有可能修订、延迟披露或具有生效时间的数据，都必须以当时可获得的信息进行计算。

### 4.6 Engine Independence

领域逻辑不得依赖 VectorBT、Qlib 或任何单一框架的私有对象。外部引擎只能作为适配器。

### 4.7 Reproducibility

任何历史结果必须可以由代码版本、配置版本、数据快照和随机种子完整重现。

## 5. 非目标

短中期明确不做：

- 高频交易、日内做市和超低延迟执行；
- 杠杆、期权和复杂衍生品组合；
- 依赖单一黑盒模型直接下单；
- 自动托管用户私钥或直接保存券商密码；
- 无审核的全自动实盘；
- 用单一收益率承诺未来表现。

## 6. 成功标准

### 工程成功

- 每次发布均通过自动化质量门禁；
- 回测结果可复现；
- 领域层与外部框架解耦；
- 新增数据源、资产或策略不需要改动全系统。

### 投资研究成功

- 相比固定战略组合，在样本外阶段改善风险调整后收益或显著降低回撤；
- 收益来源可归因，策略行为符合设计目的；
- 参数邻域稳定，成本与延迟压力测试后仍保留主要优势。

### 产品成功

- 用户可以在移动端快速理解当前资产、风险、现金和调仓建议；
- 所有动作都能追溯到数据、信号、规则和版本；
- 系统能区分策略收益、个人资金收益和财富增长。

## 7. 风险声明

Wealth OS 是研究与决策辅助系统，不保证收益。历史回测、可信区间和情景模拟均不能消除模型风险、数据风险、流动性风险、监管风险和不可观测的结构变化。
